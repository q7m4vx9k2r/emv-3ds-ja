3-D Secureによる支払認証の後、アクワイアラは次の従来の役割を果たす。

- 加盟店からオーソリゼーション要求を受け取る。
- オーソリゼーション・システムにオーソリゼーション要求を送る。
- 加盟店にオーソリゼーション応答を提供する。
- 完了した取引を決済システムに提出する。

### 2.2 相互運用ドメイン

相互運用ドメインは、次の構成要素を持つ。

- Directory Server（DS）
- Directory Server Certificate Authority（DS CA）
- オーソリゼーション・システム

### 2.2.1 Directory Server

DSは、次の機能などを実行する。

- 3DS ServerおよびACSを認証する。
- 3DS ServerとACSの間でメッセージをルーティングする。
- 3DS Server、3DS SDK、および3DS Requestorを検証する。
- 個別のプログラム規則（例えば、ロゴ、タイムアウト値など）を定める。
- 3DS ServerおよびACSの導入・登録を行う。
- ACSおよびDSのプロトコルバージョン一覧と、3DS Method URLを管理する。

### 2.2.2 Directory Server Certificate Authority

DS CAは、3DS SDK向けのDS公開鍵を生成し、3-D Secure構成要素が使用するTransport Layer Security（TLS）証明書を生成する。通常、特定のDSを担当する決済システムが運営する。証明書には次のものが含まれる。

- 3DS ServerとDSの間、およびDSとACSの間の通信に使用するTLSクライアント証明書とサーバ証明書。
- ACSから3DS SDKに渡されるデータ要素への署名に使用する証明書。
- 3DS SDKからDSに渡されるデータ要素への署名に使用する証明書。

証明書の詳細については第6章を参照すること。
