#### 手順20：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.87 [Req 70]** DSからRReqまたはErrorメッセージを受信し、5.9.9節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS Serverは処理を終了する。

**Seq 3.88 [Req 463]** Transaction Status = D、かつ3DS Requestor Decoupled Request Indicator = FまたはBの場合、Results Message Statusを04に設定する。

注：3DS Serverは、3.4節で定義するDecoupled Authenticationを伴う3RI取引を開始する。

**Seq 3.89 [Req 71]** 表B.9で定義するとおりにRResを整形し、[Req 68]で確立したセキュアな接続を使ってDSに送信する。

**Seq 3.90 [Req 346]** Decoupled Authentication取引では、RReqを受信するまで、少なくとも指定された3DS Requestor Decoupled Max Timeに1時間30秒を加えた時間だけ待機する。RReqを受信しないままの場合、それ以降の処理は3-D Secure処理の対象外である。

注：RReqを受信しない場合、3DS ServerはDecoupled Authenticationが成功しなかったとみなすことが望ましい。

注：支払認証の場合、加盟店はこの時点でアクワイアラとのオーソリゼーション処理に進むことができる。ただし、その前にカード会員が取引を放棄していないことを確認したい場合がある。

#### 手順21：DS

DSは、次を実施しなければならない。

**Seq 3.91 [Req 72]** 3DS ServerからRResまたはErrorメッセージを受信し、5.9.10節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.92 [Req 73]** DSが要求する取引情報をログに記録する。

**Seq 3.93 [Req 74]** 3DS Serverから受信したRResを、[Req 63]で確立したセキュアな接続を使ってACSに送信する。

#### 手順22：ACS

ACSは、次を実施しなければならない。

**Seq 3.94 [Req 75]** DSからRResまたはErrorメッセージを受信し、5.9.11節で定義するとおりに検証する。

メッセージにエラーがある場合、ACSは処理を終了する。

注：Decoupled Authentication取引の3-D Secure処理はここで完了する。

#### 手順23：ACS

ACSは、チャレンジフロー取引（AResのTransaction Status = C）について、手順17のCReq受信に続く処理として、次を実施しなければならない。

**Seq 3.95 [Req 470]** 3DS Requestor Decoupled Request Indicator = FまたはB、かつRReqのTransaction Status = Dの場合、Final CResのTransaction StatusをDに設定する。

**Seq 3.96 [Req 76]** Final CRes（表B.5で定義）を整形し、6.2.4.4節で定義するとおりに内容を保護する。
