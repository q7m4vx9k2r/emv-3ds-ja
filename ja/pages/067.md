**Seq 3.103 [Req 402]** ACS UI Type = 06の場合、カード会員がOOB App URLボタンを選択したとき、`HTTPS://EMV3DS/openoobApp` URLへのlocation変更を発生させるアクションを、OOBチャレンジのHTMLコードに含める。

注：ACSがHTMLコードにカード会員用の追加アクション（例えばCompleteボタン）を含める場合、[Req 164]で定義する`HTTPS://EMV3DS/challenge` URLを使用する。

#### 手順14：3DS SDK

CResにOOB App URLがある場合、3DS SDKは本手順の追加要件を実施する。[Req 54]の実施後、[Req 55]の一部として、次を実施しなければならない。

**Seq 3.104 [Req 403]** ACS UI Type = 04の場合、OOB Authentication Appへの切替に使用するOOB App Labelを持つボタンを表示する。

#### 手順15：カード会員と3DS SDKの対話

カード会員が3DS SDKのUIを操作する。例えばOOB ContinuationボタンやOOB App Labelボタンを選択する。

### 3.2.2.1 OOB App URLの要件

CResにOOB App URLがある場合、3DS SDKは次を実施しなければならない。

**Seq 3.105 [Req 472]** OOB App URLがHTTPSスキームを使用していることを確認する。

HTTPSでない場合、3DS SDKは5.9.7節で定義するエラーを返す。

**Seq 3.106 [Req 404]** ACS UI Type = 04の場合、カード会員がOOB App Labelを持つボタンを選択したとき、OOB App URLを使ってOOB Authentication Appを開くことを試みる。

**Seq 3.107 [Req 405]** ACS UI Type = 06の場合、次を実施する。

a. 特定の`HTTPS://EMV3DS/openoobApp` URLに送られるlocation変更イベントをインターセプトする。

b. OOB App URLを使ってOOB Authentication Appを開くことを試みる。

**Seq 3.108 [Req 406]** OOB Authentication Appを開く試みが成功した場合、3.2.2.2節に進む。

**Seq 3.109 [Req 407]** OOB Authentication Appを開く試みが失敗した場合（例えば、OOB App URLを開くプラットフォームのメソッドがエラーを返す場合）、次を実施する。

a. 表A.1で定義する適切な値をOOB App Statusに設定する。

b. OOB Continuation Indicator = 02を設定する。

c. カード会員によるUI操作を必要とせず、アプリ方式のフローの手順16に自動的に進む。

注：端末にOOB Authentication Appがない場合、端末のOSは既定のブラウザを使ってOOB App URLを開くことを試みる。イシュアは、このURLにWebページを用意し、OOB Authentication Appに手動で切り替える方法をカード会員に案内する。

### 3.2.2.2 3DS Requestor App URL

OOB Authentication Appが3DS Requestor App URLを呼び出すと、端末OSが3DS Requestor Appに切り替え、同アプリがフォアグラウンドになる。3DS Requestor Appは3DS SDKに制御を戻す。
