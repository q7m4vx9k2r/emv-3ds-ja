### 表1.3：定義（続き）

| 用語 | 定義 |
| --- | --- |
| Interaction Counter | ACSが取引ごとの対話回数を追跡し、RReqでDSへ送信する。選択したチャレンジフロー・セキュリティ要件に従い、事前の上限を超えず、適切なカード会員の再試行を許可する最大対話回数を設定するために使う。 |
| Interoperability Domain（相互運用ドメイン） | イシュアー・アクワイアラードメインのシステム間の情報転送を支援する。 |
| Issuer（イシュアー） | 決済カードを発行し、カード会員とカードサービスの契約を結び、3-D Secureへの参加適格性を決め、参加可能なカード番号範囲をDSに示す金融機関。 |
| Issuer Domain（イシュアードメイン） | イシュアーと顧客（カード会員）のシステム・機能を含む。 |
| JavaScript Object Notation（JSON） | 属性・値の組からなるデータオブジェクトを、人が読めるテキストで伝送する公開標準形式。通常、サーバーとWebアプリケーション間で使う。RFC参照は表1.1を参照。 |
| Key（鍵） | 暗号技術で、値の暗号化・復号に必要な値。 |
| Key management（鍵管理） | 生成、保管、入力・使用、削除・破棄、アーカイブを含む、鍵の全存続期間にわたる暗号鍵・他のセキュリティパラメーターの取り扱い。 |
| MAC | Message Authentication Code（メッセージ認証コード）。第三者による改変・偽造から送信者・受領者を保護する対称（秘密鍵）暗号方式。 |
| Merchant（加盟店） | 決済カードを受け入れるためアクワイアラーと契約する事業体。オンライン購買体験を管理し、カード番号を取得して、決済認証を行う3DS Serverへ制御を渡す。 |
| Message Category | EMV 3-D Secureメッセージの分類。決済（01-PA）または非決済（02-NPA）。 |
| Message Version | 全コンポーネントが当該3-D Secure取引を処理するため使用するProtocol Version。特定取引のすべてのプロトコルメッセージで一貫する。 |
