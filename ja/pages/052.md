# PDF 52ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

[目次](../../index.md) · [英語原文](../../en/pages/052.md) · [前ページ](./051.md) · [次ページ](./053.md)

2.1.1節で紹介したとおり、本仕様は情報を収集する特定の構成要素を指定せず、AReqを構築する際に3DS Serverが情報を利用できることのみを求める。情報には、次のものを含めることができる。

- Cardholder Account Information
- Merchant Risk Indicator
- 3DS Requestor Authentication Information
- 支払情報（支払認証の場合）
- 非支払情報
- カード会員情報

これらの情報を、本手順の要件に示す3DS SDKが収集した情報とともに、3DS Serverが利用できるようにする。

注：本手順のUI要件は4.2節で定義する。

**Seq 3.3 [Req 1]** 3DS Requestor Appとサーバ（3DS Requestorまたは3DS Server）の間の通信は、6.1.1節で定義する、サーバ認証を行うTLSセッションを使って確立しなければならない。

注：Split-SDKについては、EMV 3-D Secure Split-SDK Specificationの第4章を参照すること。

3DS Requestor Environment内の通信経路のために、妥当な時間内で3DS Serverが情報を受信できない場合は、以降の3-D Secure処理を行わず、3DS Requestor Appを通じてそのことをカード会員に通知する必要がある。

本手順の実行中、3DS SDKは次を実施しなければならない。

**Seq 3.4 [Req 2]** Device Information、SDK Reference Number、およびSDK App IDを取得する。詳細は、適用される3DS SDK仕様および本仕様の附属書Aを参照すること。

**Seq 3.5 [Req 3]** 3-D Secure認証のSDK Transaction IDを生成する。

このIDは、認証処理内のすべてのメッセージ（AReq／ARes、CReq／CRes、RReq／RRes）で、3DS SDKにとってこの取引を一意に識別する。

**Seq 3.6 [Req 4]** 表A.1で定義するとおりにDevice Rendering Options Supportedデータ要素を設定する。

**Seq 3.7 [Req 5]** 6.2.2.1節で定義するとおりに、DS公開鍵を使ってDevice Informationを暗号化する。

**Seq 3.8 [Req 6]** 6.2.3.1節で定義するとおりに、3DS SDKとACSの間のセキュアな通信経路を準備する。

#### 手順5：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.9 [Req 7]** 6.2.1節で定義するとおりに3DS SDKの真正性を検証する。

3DS Serverが3DS SDKの真正性を検証できない場合は、3-D Secure処理を終了する。
