#### 手順10f：DS

DSは、ブラウザ方式の手順7で定義する要件を実施する。

3DS Requestor Prior Transaction Referenceで受信した前のACS Transaction IDを通じて、このAReqの情報を前のAReqの情報と関連付けることができる。

**Seq 3.252 [Req 451]** DSがACSに代わってAssertion Dataを評価する場合、対応するDS Authentication Information Verification Indicatorに検証結果を含めなければならない。

#### 手順10g：ACS

ACSは、ブラウザ方式の手順8の要件を実施し、その一部としてAReqで受信したAssertion Dataを評価する。

次の条件に基づき、[Req 107]で定義する取引の処置（例えば、認証済み［Transaction Status = Y］、または追加のチャレンジが必要［Transaction Status = C］）を判定する。

- Assertion Dataの署名の検証。
- 最初と2回目のAReq間での取引データの整合性。
- Assertion DataとAReqのデータとの整合性。

3DS Requestor Prior Transaction Referenceで受信した前のACS Transaction IDを通じて、このAReqの情報を前のAReqの情報と関連付けることができる。

#### 手順10h：DS

DSは、ブラウザフローの手順9で定義する要件を実施する。

#### 手順10i：3DS Server

3DS Serverは、ブラウザフローの手順10で定義する要件を実施する。

注：Assertion Dataを正しく検証できた場合、追加のチャレンジは不要で、3DS ServerはTransaction Status = YのAResを受信すると想定される。そのため、以降の3DS処理は不要である。手順10gの取引処置の判断でTransaction Status = Cとなった場合にのみ、手順11〜22を実行する。

### 3.5.2 ACSがSPC認証を開始する場合

ACSがチャレンジの一部としてSPC認証を開始・実施する場合、他の3DSチャレンジ方法の代わりにSPC認証を使用する点を除き、手順は標準のブラウザフロー（図3.3参照）と同じである。

本節では、ACSがチャレンジフローの一部としてSPC認証を実施する場合の、特定の手順の詳細と値を概説する。手順は図3.3を参照する。図3.3の手順が本節で参照されていなければ、その手順にはSPC認証固有の機能はない。

**手順8：** ACSが、このカード会員の端末上の事前登録済みFIDO Authenticatorを認識する。Authentication Method = 14（SPC）とTransaction Status = Cを組み合わせて選択し、チャレンジ方法としてSPC認証を実施する意図を3DS Serverに示す。

**手順12：** ACSは、例えばJavaScriptを使い、このカード会員と端末について登録されたクレデンシャルを対象にSPC認証（SPC API）を呼び出す。
