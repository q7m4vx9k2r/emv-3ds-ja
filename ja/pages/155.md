# PDF 155ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

[目次](../../index.md) · [英語原文](../../en/pages/155.md) · [前ページ](./154.md) · [次ページ](./156.md)

3DS ServerはPReq（表B.6で定義）を整形し、DSに送信する。キャッシュの初回読込み、キャッシュ消去後の再読込み、またはDSが部分更新に対応しない場合、要求にSerial Numberを含めない。これによりDSは、参加するカード範囲情報の全一覧を返す。

それ以外では、最後に処理したPResのSerial Numberを含め、DSは前のPRes以降の変更だけを返す。DSと3DS ServerがCard Range Data Fileのダウンロードを使用する場合、Serial Numberは使用・提供しない。

DSは、特定のSerial Numberに対するPReqの応答に、その番号の発行以降のすべての更新が含まれるよう、Serial Numberを管理する。要求のSerial Numberが無効な場合（例えば古すぎて見つからない場合）、Error Code = 307のErrorメッセージ（A.9節で定義）を応答することが望ましい。

PReqにSerial Numberがない場合、DSのPRes応答またはファイルはすべてのカード範囲項目を含む。Serial Numberが変わっていない場合、DSはCard Range Dataを返さず、PResにSerial Numberを含める。

3DS Serverは、次を実施しなければならない。

**Seq 5.77 [Req 246]** 登録済みの各DSを次の更新のために呼び出す。

- すべてのCard Range Dataの更新（Serial Numberなし）を、最大12時間ごとに行う。受信データにエラーがある場合、完全または部分更新のため、各DSを最大でも1時間に1回呼び出す。
- Serial Numberを提供する部分更新を、最大でも1時間に1回行う。

**Seq 5.78 [Req 425]** HTTP要求に`Accept-Encoding: gzip`を追加し、圧縮形式でCard Range Dataを要求する。

**Seq 5.79 [Req 456]** PReqにCard Range Data Download Indicatorがある場合、RFC 7233で定義するRange Requestsに対応する。

**Seq 5.80 [Req 247]** 6.1.2.1節で定義するとおりに確立したDSとのセキュアな接続を使い、PReqを送信する。

**Seq 5.81 [Req 248]** DSへの最初のTCP/IP接続とTLSハンドシェイクを完了できない場合、直ちに接続を再試行する。

**Seq 5.82 [Req 249]** 2回目も完了できない場合、取引を終了し、正常に完了するまで24時間の期間内で60秒間隔の定期的な再試行を行う。

DSは、次を実施しなければならない。

**Seq 5.83 [Req 428]** 3DS ServerのHTTP要求ヘッダーに`Accept-Encoding: gzip`がない場合、Errorメッセージを返さず、非圧縮形式でデータを返す。

**Seq 5.84 [Req 303]** PReqを受信して表B.6に従って検証する。次の条件ではError Component = DのErrorメッセージ（A.9節で定義）を3DS Serverに返す。

- 存在するデータ要素が検証に失敗した場合：Error Code = 203。
