**Seq 3.176 [Req 128]** Transaction Status = CまたはDの各AResに対して、1つのRReqをDSに送信することを確実にする。

**Seq 3.177 [Req 347]** Decoupled Authentication取引について、次を確実にする。

- 成否にかかわらず、認証結果を取得したら直ちにRReqを送信する。
- 3DS Requestor Decoupled Max Timeが満了した場合、1時間の猶予期間を設けて、認証結果を含まないRReq（Transaction Status = U）を送信する。

注：Transaction Status = UのRReqには、Transaction Status Reason = 24または26、およびChallenge Cancelation Indicator = 03を含めることを推奨する。

#### 手順17：DS

DSは、次を実施しなければならない。

**Seq 3.178 [Req 129]** ACSからRReqを受信し、5.9.8節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.179 [Req 130]** AReqから取得し[Req 99]で保存した3DS Server URLデータ要素を使い、6.1.2.2節で定義するとおりに3DS Serverとのセキュアな接続を確立する。

**Seq 3.180 [Req 131]** [Req 130]で確立したセキュアな接続を使って、RReqを3DS Serverに送信する。

#### 手順18：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.181 [Req 132]** DSからRReqまたはErrorメッセージを受信し、5.9.9節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS Serverは処理を終了する。

**Seq 3.182 [Req 466]** Transaction Status = D、かつ3DS Requestor Decoupled Request Indicator = FまたはBの場合、Results Message Statusを04に設定する。

注：3DS Serverは、3.4節で定義するDecoupled Authenticationを伴う3RI取引を開始する。

**Seq 3.183 [Req 133]** 表B.9で定義するとおりにRResを整形し、[Req 130]で確立したセキュアな接続を使ってDSに送信する。

**Seq 3.184 [Req 348]** Decoupled Authentication取引では、RReqを受信するまで、少なくとも指定された3DS Requestor Decoupled Max Timeに1時間30秒を加えた時間だけ待機する。RReqを受信しないままの場合、それ以降の処理は3-D Secure処理の対象外である。

注：RReqを受信しない場合、3DS ServerはDecoupled Authenticationが成功しなかったとみなすことが望ましい。

注：支払認証の場合、加盟店はこの時点でアクワイアラとのオーソリゼーション処理に進むことができる。ただし、その前にカード会員が取引を放棄していないことを確認したい場合がある。
