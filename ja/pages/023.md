### 表1.3：定義（続き）

| 用語 | 定義 |
| --- | --- |
| Authentication Value（AV、認証値） | 承認処理時に、承認システムが認証結果の完全性を検証する手段としてACSが生成する暗号値。AVアルゴリズムは各決済システムが定める。 |
| Authorisation（承認） | イシュアー、またはその代理のプロセッサーが、取引の支払いを承認するプロセス。 |
| Authorisation System（承認システム） | 決済システムが、イシュアー・アクワイアラーにオンライン金融処理、承認、クリアリング、決済サービスを提供するシステム・サービス。 |
| Bank Identification Number（BIN） | 発行金融機関を一意に識別する、決済カードアカウント番号の先頭6桁または8桁。ISO 7812ではIssuer Identification Number（IIN）とも呼ぶ。 |
| Base64 | RFC 2045で定義され、Authentication Valueデータ要素に適用する符号化。 |
| Base64url | RFC 7515で定義され、3DS Method Data、Device Information、WebAuthn Credential List、CReq/CResメッセージに適用する符号化。 |
| Browser（ブラウザー） | Chrome、Safari、Edge、Firefoxなど、World Wide Webの情報にアクセスする専用アプリケーション。Webページが要求されるとサーバーから必要な内容を取得し、コンシューマーの画面に表示する。3-D Secureではアクワイアラードメインとイシュアードメイン間のメッセージ伝送路。モバイルアプリ内のコンテンツ表示に用いるWebView・Custom TabsなどのUIコンポーネントとは区別する。ブラウザーフローはブラウザーから開始するもので、本EMVCo仕様はアプリ内UIコンポーネントからのブラウザーフロー開始をサポートしない。 |
| Card（カード） | 本仕様では決済カードのアカウントと同義。 |
| Card Range Data File | JSONのCard Range Dataオブジェクトを含むファイル。ACSが扱うカード番号範囲について、サポートする3DSプロトコルのバージョンと、3DS Method・Message Extensionなどの任意情報を3DS Serverに提供する。 |
| Cardholder（カード会員） | カードが発行された人、または当該カードの使用を許可された人。 |
| Certificate（証明書） | 所有者の公開鍵を含む電子文書。認証局（CA）が証明し、CA秘密鍵による署名という暗号技術で偽造を防ぐ。 |
| Certificate Authority（CA、認証局） | 証明書を発行・失効させる信頼できる主体。DS Certificate Authorityも参照。 |
| Challenge（チャレンジ） | ACSが3DS Clientと通信し、カード会員との対話を通じて追加情報を取得するプロセス。 |
