### 表1.3：定義（続き）

| 用語 | 定義 |
| --- | --- |
| Challenge Flow（チャレンジフロー） | 2.5.2節で定義される、カード会員との対話を伴う3-D Secureフロー。 |
| Challenge Request（CReq）Message | 認証を支援するためカード会員からACSへ追加情報を送る、3DS SDKまたは3DS Serverが送信するEMV 3-D Secureメッセージ。 |
| Challenge Response（CRes） | CReqへのACS応答。カード会員認証の結果を示せる。アプリベースでは、認証完了にさらにカード会員との対話が必要なことも示せる。 |
| Consumer Device（コンシューマーデバイス） | スマートフォン、ノートパソコン、タブレットなど、カード会員が認証・購入を含む決済行為に使用する機器。 |
| Decoupled Authentication（分離認証） | カード会員の3DS Requestorでの操作体験とは独立して認証できる方法。具体的な認証方式は本仕様の範囲外。例えば、銀行アプリへのプッシュ通知で認証を完了し、結果をACSに送る方法がある。全デバイスチャネルに適用できる。 |
| Decoupled Authentication Fallback | チャレンジ中のACSの追加選択肢。RReqでTransaction Status = Dを返し、分離認証を使う後続の3DS認証を3DS Serverに開始するよう要求する。 |
| Device Binding | 本仕様では、取引に使用したコンシューマーデバイスをカード会員アカウントおよび／またはカード会員に結び付けるプロセス。 |
| Device Channel | 取引の起点チャネル。アプリベース（01-APP）、ブラウザーベース（02-BRW）、3DS Requestor起点（03-3RI）のいずれか。 |
| Device Information | デバイスが提供し、認証プロセスに使用するデータ。 |
| Digital signature（デジタル署名） | 受領者がデータの出所・完全性を証明できる非対称暗号方式。第三者による改変・偽造から送信者・受領者を保護し、受領者による偽造から送信者を保護する。 |
| Digital wallet（デジタルウォレット） | クレジットカードなどの金融手段で電子決済できるソフトウェア。アカウント番号入力、配送情報・カード会員識別情報の提供など、決済プロトコル実行の低水準の詳細を隠す。 |
