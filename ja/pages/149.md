追加データ要素の形式を確認する場合：

- 形式が正しければ、その要素を無視し、フロー内の次の3DS構成要素へ送らない。
- 形式が正しくなければ、受信側3DS構成要素は送信元にErrorメッセージを返す。

例：DSが3DS Serverから、AReqのMessage Type、Device Channel、Message Categoryについて表A.1で指定されていない追加要素を含むAReqを受信する。DSは内容を検証し、ACSにAReqを送信する際に追加要素を除去する。または、追加要素が形式確認に合格しない場合、DSは3DS ServerにErrorメッセージを返すことができる。

**Seq 5.37 [Req 210]** すべての3-D Secure構成要素は、認識しない非クリティカルな拡張の名前／値の組（すなわちcriticality属性の値がtrueでない拡張）を無視し、そのまま引き渡さなければならない。

**Seq 5.38 [Req 434]** データ要素の値が「Reserved for EMVCo future use」の範囲にある場合、すべての3DS構成要素は、適切なError ComponentとError Code = 207を持つErrorメッセージ（A.9節で定義）を返さなければならない。

注：「Reserved for DS use」の範囲の値に対するエラー要件とError Code = 207の使用は、DSが定義する。

内容検証の要件：

**Seq 5.39 [Req 212]** 3-D Secure構成要素は、Transaction IDとReference Numberを含む、表A.1で定義する応答メッセージのデータ要素が、対応する要求メッセージと一致することを確実にしなければならない。

**Seq 5.40 [Req 213]** メッセージのデータ要素が形式検証に合格しない場合、検証側構成要素は、不正な要素の名前をError Detailに設定した応答を生成しなければならない。詳細は表A.4を参照すること。

注：AReqには、データ要素の内容に基づく追加のメッセージ内容検証要件がある。

### 5.2 部分的なシステム停止

3-D Secure構成要素は、実質的に稼働できなくなるシステム障害に遭遇する場合がある。

**Seq 5.41 [Req 215]** システム障害を検出した場合、修復されるまで要求の受付を停止しなければならない。処理中のすべての要求について、適切なError ComponentとError Code = 403または404を持つErrorメッセージ（A.9節で定義）を送信しなければならない。
