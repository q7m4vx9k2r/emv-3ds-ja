#### 手順8：ACS

ACSは、Decoupled Authentication取引（初期のTransaction Status = D）について、[Req 330].bの認証が完了するか[Req 330].aのタイマーが満了した時点で、次を実施しなければならない。

**Seq 3.230 [Req 349]** 表B.8で定義するとおりにRReqを整形する。

**Seq 3.231 [Req 350]** 6.1.3.2節で定義するとおりにDSとのセキュアな接続を確立する。

**Seq 3.232 [Req 351]** RReqをDSに送信する。

**Seq 3.233 [Req 352]** Transaction Status = Dの各AResに対して、1つのRReqをDSに送信することを確実にする。

**Seq 3.234 [Req 353]** 次を確実にする。

- 成否にかかわらず、認証結果を取得したら直ちにRReqを送信する。
- 3DS Requestor Decoupled Max Timeが満了した場合、1時間の猶予期間を設けて、認証結果を含まないRReq（Transaction Status = U）を送信する。

注：Transaction Status = UのRReqには、Transaction Status Reason = 24または26、およびChallenge Cancelation Indicator = 03を含めることを推奨する。

#### 手順9：DS

DSは、次を実施しなければならない。

**Seq 3.235 [Req 332]** ACSからRReqを受信し、5.9.8節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.236 [Req 333]** AReqから取得した3DS Server URLを使い、6.1.2.2節で定義するとおりに3DS Serverとのセキュアな接続を確立する。

**Seq 3.237 [Req 334]** [Req 333]で確立したセキュアな接続を使って、RReqを3DS Serverに送信する。

#### 手順10および11：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.238 [Req 335]** DSからRReqまたはErrorメッセージを受信し、5.9.9節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS Serverは処理を終了する。

**Seq 3.239 [Req 336]** 表B.9で定義するとおりにRResを整形し、[Req 333]で確立したセキュアな接続を使ってDSに送信する。

**Seq 3.240 [Req 354]** Decoupled Authentication取引では、RReqを受信するまで、少なくとも指定された3DS Requestor Decoupled Max Timeに1時間30秒を加えた時間だけ待機する。RReqを受信しないままの場合、それ以降の処理は3-D Secure処理の対象外である。

注：RReqを受信しない場合、3DS ServerはDecoupled Authenticationが成功しなかったとみなすことが望ましい。

**Seq 3.241 [Req 337]** 適切な応答を3DS Requestorに伝える。
