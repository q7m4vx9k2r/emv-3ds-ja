### 4.2.7 HTMLのメッセージ交換要件

本節では、アプリ方式のHTML UIの要件を示す。

### 4.2.7.1 3DS SDK

3DS SDKは、次を実施しなければならない。

**Seq 4.49 [Req 159]** ACSにCReqを送信した後、CResを受信するかタイムアウトを超えるまで、3DSアプリの処理中画面を表示する。

### 4.2.7.2 ACS

ACSは、次を実施しなければならない。

**Seq 4.50 [Req 160]** 提供するHTMLに、画面遷移の試みや外部リソース要求など、外部参照を含めないことを確実にする。

**Seq 4.51 [Req 161]** Webビュー内で処理・描画するCSSと画像データを、すべてHTML内に埋め込む。

**Seq 4.52 [Req 162]** レスポンシブデザインの原則に従い、CSSとロゴを含む完全なHTML文書を提供する。

**Seq 4.53 [Req 163]** すべてのリソースをACS提供のHTMLに埋め込み、外部URLを通じて取得しない。

**Seq 4.54 [Req 164]** ACS UI Type = 05の場合、およびACS UI Type = 06でOOBの手動アプリ切替を使用する場合に限り、カード会員がデータ入力を完了してSubmitを押したとき、指定URL（`HTTPS://EMV3DS/challenge`）へのlocation変更を発生させるアクションをACS HTMLに含める。

注：ACSは、上記のlocation設定手法により、セキュアなCReq／CRes経路を通じて自身に通信を返す。

**Seq 4.55 [Req 165]** 3DS SDKを迂回したり、自身へ直接接続したりしない。

その後ACSは、3.1節の要件で定義するとおり、3DS SDKを通じたセキュアなCReq／CRes経路を使って消費者端末と通信する。
