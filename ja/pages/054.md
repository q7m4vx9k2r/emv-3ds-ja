**Seq 3.22 [Req 17]** 6.2.2.2節で定義するとおりにAReqのSDK Encrypted Dataデータ要素を復号する。得られた内容をBase64urlでエンコードし、ACS向けのAReqのDevice Informationデータ要素に格納する。

復号に失敗した場合、DSは3DS Serverに、Error Component = D、Error Code = 302のErrorメッセージ（A.9節で定義）を返し、処理を終了する。

**Seq 3.23 [Req 18]** DSとACSがMessage Version Numberに対応していることを確認する。

対応していない場合、DSは3DS Serverに次のいずれかを返し、処理を終了する。

- 個々のDSが定義する適切な応答をTransaction Statusに設定したARes（表B.2で定義）。
- Error Component = D、Error Code = 102のErrorメッセージ（A.9節で定義）。

**Seq 3.24 [Req 19]** AReqのデータ要素を次のとおり確認する。

- 3DS Server Reference Numberが参加する3DS Serverを表していない、またはSDK Reference Numberが参加する3DS SDKを表していない場合、DSは3DS Serverに、Error Component = D、Error Code = 303のErrorメッセージ（A.9節で定義）を返し、処理を終了する。
- Merchant Category Code（MCC）が当該DSで有効でない場合、DSは3DS Serverに、Error Component = D、Error Code = 306のErrorメッセージ（A.9節で定義）を返し、処理を終了する。

**Seq 3.25 [Req 20]** AReqで受信したCardholder Account Numberが、参加するアカウント範囲に含まれるかを判定する。

含まれない場合、DSは3DS Serverに、個々のDSが定義する適切な値をTransaction Statusに設定したARes（表B.2で定義）を返し、処理を終了する。

**Seq 3.26 [Req 21]** Cardholder Account Numberが、3-D Secureメッセージを処理できるACSを持つアカウント範囲に含まれるかを判定する。

含まれない場合、DSは3DS Serverに、個々のDSが定義する適切な値をTransaction Statusに設定したARes（表B.2で定義）を返し、処理を終了する。

**Seq 3.27 [Req 22]** 後にRReqを処理する可能性に備え、3DS Server URLをDS Transaction IDとともに保存する。

**Seq 3.28 [Req 23]** 6.1.3.1節で定義するとおりにACSとのセキュアな接続を確立する。

ACSとの接続を確立できない場合、DSは[Req 233]に従って処理し、処理を終了する。

注：DSは複数のACS URLを管理してもよい。最初に試したURLが利用できない場合、代替URLのいずれかへの接続を試みる。
