3DS SDKによるUI描画処理の詳細は、EMV 3-D Secure SDK—Technical Guideで別途説明する。

UIの内容はイシュアが提供するが、その描画は3DS SDKの責任である。そのため3DS SDKは、消費者端末上で最適に表示されるようUIを調整できる。端末の画面サイズ、向き、フォントサイズなどを把握しているため、イシュアの提供内容を最適化できる（例えば、スクロールの原因となる余分な改行を削除する）。イシュアは、CResで提供した書式が、カード会員に表示されるものと厳密には一致しない場合があることを理解することが望ましい。

### 4.2.2.1 3DS SDK／ACS

3DS SDKは、CReq／CResのやり取りについて次を実施しなければならない。

**Seq 4.19 [Req 362]** ACS UI TypeとApp Screen Orientationについて、表A.20で定義し図4.1および図4.2に示す該当ゾーンと順序で、提供されたすべてのUIデータ要素を表示する。想定される形式は4.2.3節および4.2.6節に示す。

当該ACS UI TypeでサポートしないUIデータ要素を受信した場合、3DS SDKはそれらを表示せず、チャレンジを続行し、ACSにErrorメッセージは送らない。

**Seq 4.20 [Req 398]** 当該ACS UI Typeについて、表A.20で定義する必須のUIデータ要素が欠けている場合、Error Component = C、Error Code = 201のErrorメッセージ（A.9節で定義）をACSに返す。

**Seq 4.21 [Req 363]** ACSがCResで提供した改行を解釈し、画面に配置する。

**Seq 4.22 [Req 364]** Branding、Challenge／Processing、Informationゾーンには、ACSがCResで提供したもの以外のUI要素を表示しない。

**Seq 4.23 [Req 365]** Expandable Information Labelを、展開できるグラフィカルなコントロール（例えばアコーディオン）として表示する。

**Seq 4.24 [Req 366]** カード会員がExpandable Information Labelを選択した場合にのみ、Expandable Information Textを表示する。

**Seq 4.25 [Req 367]** Why Information Labelを、展開できるグラフィカルなコントロール（例えばアコーディオン）として表示する。

**Seq 4.26 [Req 368]** カード会員がWhy Information Labelを選択した場合にのみ、Why Information Textを表示する。

**Seq 4.27 [Req 369]** Cancelアクションを提供する。図4.1および図4.2のとおりHeaderゾーンの上隅にあるボタン、またはプラットフォームのコントローラの機能、もしくはその両方として実装できる。

**Seq 4.28 [Req 392]** Trust List Information Textの既定設定をOffとして表示する。これによりTrust List Data EntryにY値を生成するにはカード会員の操作が必要となる。

**Seq 4.29 [Req 446]** Device Binding Information Textの既定設定をOffとして表示する。これによりDevice Binding Data EntryにY値を生成するにはカード会員の操作が必要となる。

ACSは、CReq／CResのやり取りについて次を実施しなければならない。

**Seq 4.30 [Req 387]** 表A.20で定義する、選択したACS UI TypeでサポートするUIデータ要素のうち、ACSが選択したものだけを含める。
