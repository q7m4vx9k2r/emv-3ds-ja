### 5.9.8.1 メッセージにエラーがある場合

DSは、AReqから取得し、アプリ方式では[Req 22]、ブラウザ方式では[Req 99]、3RI方式では[Req 427]で保存した3DS Server URLを使って、6.1.2.2節で定義するセキュアな接続を確立する。

3DS Serverに、Error Component = Dと、ACSに返したものと同じError Codeを持つErrorメッセージ（A.9節で定義）を送る。

### 5.9.9 3DS ServerによるRReqのエラー処理

3DS Serverは、RReqまたはErrorメッセージの検証を次のとおり処理する。以下のErrorメッセージはA.9節で定義する。

- 認識できないメッセージの場合、DSにError Component = S、Error Code = 101を返す。特定の取引を識別できれば、3DS Requestor Environmentにエラーの発生を通知する。
- RReqの場合、表B.8と5.1.7節に従って検証する。存在するデータ要素が検証に失敗した場合、DSにError Component = S、Error Code = 203を返す。特定の取引を識別できれば、3DS Requestor Environmentにエラーの発生を通知する。
- 必須データ要素が欠ける場合、DSにError Component = S、Error Code = 201を返す。特定の取引を識別できれば、3DS Requestor Environmentにエラーの発生を通知する。
- それ以外ではメッセージにエラーはない。
- Errorメッセージの場合、特定の取引を識別できれば、3DS Requestor Environmentにエラーの発生を通知する。
