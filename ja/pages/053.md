# PDF 53ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

**Seq 3.10 [Req 300]** 3DS Requestorと3DS Serverが別の構成要素である場合、両方のサーバの相互認証を行い、両構成要素間で転送するデータが決済システムのセキュリティ要件を満たす水準で保護されるようにする。

要求どおりに通信を確立できない場合、3DS Serverは3-D Secure処理を終了する。

**Seq 3.11 [Req 8]** 3DS Server Transaction IDを生成する。

**Seq 3.12 [Req 9]** 3DS Requestor ID、3DS Server Reference Number、および条件付きでAcquirer BINを取得する。

**Seq 3.13 [Req 10]** 3DS Requestor Environment内の構成要素が収集した、AReqに必要な情報（表B.1で定義）が利用可能であることを確認する。

必要な情報を利用できない場合、3DS Serverは3-D Secure処理を終了する。

**Seq 3.14 [Req 12]** 6.1.2.1節で定義するとおりにDSとのセキュアな接続を確立する。

DSとの接続を確立できない場合、3DS Serverは3-D Secure処理を終了する。

PResの情報を利用できない場合、3DS Serverは自身が対応するMessage Version Numberを使用してもよい。

**Seq 3.15 [Req 13]** 表B.1で定義するとおりにAReqを整形する。

**Seq 3.16 [Req 14]** [Req 12]で確立したセキュアな接続を使って、AReqをDSに送信する。

DSとの通信で失敗が通知された場合、または応答を受信しない場合（5.5節で定義）、3DS Serverは3-D Secure処理を終了する。

#### 手順6：DS

DSは、次を実施しなければならない。

**Seq 3.17 [Req 15]** 3DS ServerからAReqを受信し、5.9.1節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.18 [Req 390]** SDK Type = 02の場合、6.2.2.4節で定義するとおりにSDK Server Signed Contentの署名を検証する。

検証に失敗した場合、DSは3DS Serverに、Error Component = D、Error Code = 308のErrorメッセージ（A.9節で定義）を返し、処理を終了する。

**Seq 3.19 [Req 394]** SDK TypeおよびSDK Reference Numberが、DSの規則に従ってこの取引で有効かどうかを判定する。

有効でない場合、DSは3DS Serverに、Error Component = D、Error Code = 305のErrorメッセージ（A.9節で定義）を返し、処理を終了する。

**Seq 3.20 [Req 16]** DS Transaction IDを生成する。

**Seq 3.21 [Req 420]** SDK Encrypted Dataの鍵識別子（kid）から、3DS SDKがDevice Informationの暗号化に使用したDS公開鍵を識別する。
