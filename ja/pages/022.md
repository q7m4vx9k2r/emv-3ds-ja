### 表1.3：定義（続き）

| 用語 | 定義 |
| --- | --- |
| Abandon（中断） | チャレンジ中に、カード会員がキャンセル操作で取引を離れること。例は、アプリのチャレンジUIのキャンセルボタンの使用。 |
| Absent（不在） | メッセージ内に名前・値の組が存在しないとき、その要素が存在しないことを示す。本書の例では、下のJSONに `firstName` 要素は存在しない。 |
| Access Control Server（ACS） | イシュアードメインで動作し、カード番号・デバイス種別について認証が利用可能かを検証し、特定のカード会員を認証するコンポーネント。 |
| Access Control Server User Interface（ACS UI） | カード会員チャレンジ中に生成され、ブラウザーのチャレンジiframe内でACSが描画するUI。 |
| Acquirer（アクワイアラー） | 決済カード受け入れのため、加盟店とサービス契約関係を結ぶ金融機関。従来の承認・決済メッセージの受送信（インターチェンジへの取引投入）に加え、3-D Secureでは、加盟店が3-D Secureに参加する適格性も判断する。 |
| Acquirer Domain（アクワイアラードメイン） | 3DS Requestor Environmentのシステム・機能と、任意でアクワイアラーを含む。 |
| App Screen Orientation（アプリ画面の向き） | デバイス上のアプリ表示の向き。縦・横の一方のみをサポートする場合、マルチウィンドウ・分割画面などでは、デバイスの向きと異なることがある。幅が高さより大きければ横向き、それ以外は縦向きとする。 |
| Attempts（認証試行） | 決済認証が利用できない場合、認証を試みた証拠を生成するプロセス。サポートの有無は各DSが定める。 |
| Authentication（認証） | 3-D Secureでは、電子商取引を行う人に決済カードを使用する資格があることを確認するプロセス。 |
| Authentication Request（AReq）Message | 認証プロセスを開始するため、3DS ServerがDSを経由してACSへ送信するEMV 3-D Secureメッセージ。 |
| Authentication Response（ARes）Message | 認証要求メッセージへの応答として、ACSがDS経由で返すEMV 3-D Secureメッセージ。 |
