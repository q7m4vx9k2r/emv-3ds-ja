### 5.9.3.1 メッセージにエラーがある場合

DSは、メッセージにエラーがあり特定の取引を識別できる場合、アプリ方式では[Req 12]、ブラウザ方式では[Req 90]、3RIでは[Req 275]で確立したセキュアな接続を使い、次のいずれかを3DS Serverに送る。

- Error Component = Dと、ACSに返したError Codeを持つErrorメッセージ（A.9節で定義）。
- 当該DSが定義する適切な値をTransaction Statusに設定したARes（表B.2で定義）。

### 5.9.3.2 Errorメッセージを受信した場合

DSは、Errorメッセージを受信して特定の取引を識別できる場合、アプリ方式では[Req 12]、ブラウザ方式では[Req 90]、3RIでは[Req 275]で確立したセキュアな接続を使い、次のいずれかを3DS Serverに送る。

- ACSから受信したErrorメッセージ。
- 当該DSが定義する適切な値をTransaction Statusに設定したARes（表B.2で定義）。

### 5.9.4 3DS ServerによるAResのエラー処理

3DS Serverは、AResまたはErrorメッセージの検証を次のとおり処理する。

認識できないメッセージの場合：

- DSに、Error Component = S、Error Code = 101のErrorメッセージ（A.9節で定義）を返す。
- 特定の取引を識別できる場合、3DS Requestor Environmentにエラーの発生を通知する。

AResの場合、表B.2と5.1.7節に従って検証する。データ要素が検証に失敗した場合の処理は次ページに続く。
