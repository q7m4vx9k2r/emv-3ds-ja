#### 手順17：ACS

ACSは、次を実施しなければならない。

**Seq 3.73 [Req 60]** 3DS SDKからCReqまたはErrorメッセージを受信し、5.9.5節で定義するとおりに検証する。

メッセージにエラーがある場合、ACSは処理を終了する。

**Seq 3.74 [Req 310]** Challenge Cancelation Indicatorに値がある場合、手順18に進む。

**Seq 3.75 [Req 461]** ACSがDecoupled Authentication Fallbackを必要と判断し、3DS Requestor Decoupled Request Indicator = FまたはBの場合、第4章で定義するInformation UIテンプレートを使い、追加のCResによってDecoupled Authenticationをカード会員に通知する。その後、Final CResを準備するため[Req 61]に進む。

**Seq 3.76 [Req 61]** CReqで受信したデータを確認し、認証の状態を評価する。

- ACSがDecoupled Authentication Fallbackを選択した場合、手順18に進む。
- 認証に成功した場合、ACSはInteraction Counterを増分し、Transaction Status = Yを設定する。当該DSが定義するECI値を設定し、DSが定義するAuthentication Valueを生成する。Challenge Completion Indicator = Yを設定し、手順18に進む。
- 認証に失敗した場合、または認証が未完了の場合、ACSはInteraction Counterを増分し、ACSのチャレンジ最大回数と比較する。

Interaction Counter ≥ ACSのチャレンジ最大回数、または認証に失敗した場合、ACSは次を実施する。

- Transaction Status = Nを設定する。
- Transaction Status Reason = 19を設定する。
- 当該DSが定義するECI値を設定する。
- Challenge Completion Indicator = Yを設定する。
- 手順18に進む。

それ以外で、Interaction Counter < ACSのチャレンジ最大回数、かつ認証が未完了の場合、ACSは次を実施する。

- 選択されたチャレンジ方法とACS UI Typeに従い、消費者端末にチャレンジを再表示するために必要な情報を取得する。
- 手順13に進む。
