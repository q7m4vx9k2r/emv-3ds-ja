**Seq 5.100 [Req 260]** 3DS Method Dataの要素を含むJSONオブジェクトを作成し、Base64urlでエンコードする。

**Seq 5.101 [Req 261]** カード会員のブラウザに、表A.23で定義するiframe属性と、表A.24で定義するsandbox属性を持つ非表示のHTML iframeを開く。

ブラウザ互換性のため、スタイル設定`visibility: hidden`（例えば`style="visibility:hidden"`）でiframeを非表示にしなければならない。

JSONオブジェクトを含む`threeDSMethodData`というフィールドを持つフォームを、HTTP POSTによって、PResのキャッシュから取得したACSの3DS Method URLに送信する。

ACSは、次を実施しなければならない。

**Seq 5.102 [Req 262]** HTML iframeを介してカード会員のブラウザと対話し、該当する値を3DS Server Transaction IDとともに保存する。同じIDを含むAReqを受信した際に使用する。

**Seq 5.103 [Req 263]** 最初の3DS POST methodで受信したBase64urlエンコード済み`threeDSMethodData`を、パディングの有無にかかわらず検証し、3DS Server Transaction IDを取得する。その後JSONオブジェクトをBase64urlでエンコードし、ブラウザのHTML iframe内の`threeDSMethodData`フィールドを持つフォームを使い、HTTP POSTで3DS Method Notification URLに送信する。詳細は表A.2を参照すること。

3DS Serverは、次を実施しなければならない。

**Seq 5.104 [Req 315]** 3DS Requestorからの通知で3DS Method Completion Indicator = Yを設定する。3DS Methodが5秒以内に完了しない場合はNを設定する。

注：3DS Methodの完了通知を受けた時点で、3DS ServerはAReqを送信できる。

ACS：

**Seq 5.105 [Req 264]** 3DS Method実行中のどの動作も利用体験に影響しないようにすることが望ましい。

### 5.8.1.2 直近の3DS Method呼出しがある場合

過去10分以内の3DS Method呼出しがある場合、本節の要件を適用する。

**Seq 5.106 [Req 415]** 3DS Requestorが、過去10分以内に同じ端末・ブラウザで同じCardholder Account Numberの3DS Methodを処理済みの場合、以前の実行を使用し、新しい呼出しを行わないことを選んでもよい。

以前の呼出しを使用する場合、3DS ServerはAReqの3DS Method IDに前の取引の3DS Server Transaction IDを、Method Completion IndicatorにYを設定しなければならない。

### 5.8.2 ブラウザチャレンジのiframe要件

ブラウザチャレンジはカード会員のブラウザ内で行い、ACSは整形したチャレンジ用UIを、ブラウザのチャレンジ用iframe内でカード会員に提供する。
