# PDF 56ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

[目次](../../index.md) · [英語原文](../../en/pages/056.md) · [前ページ](./055.md) · [次ページ](./057.md)

ACSは、次を実施しなければならない。

**Seq 3.37 [Req 30]** AReqで受信した値を評価し、取引〔注1〕が次のいずれに該当するかを判定する。

- 認証済み（Transaction Status = Y）。
- 認証の完了にカード会員のチャレンジが必要（Transaction Status = C）。
- Decoupled Authenticationによるカード会員のチャレンジが必要（Transaction Status = D）。
- 未認証（Transaction Status = N）。
- 未認証だが、認証試行の証明（Authentication Value）を生成済み（Transaction Status = A）〔注2〕。
- 技術上またはその他の問題により認証できず、未認証（Transaction Status = U）。
- イシュアが認証を拒否し、オーソリゼーションを試みないよう要求しているため未認証（Transaction Status = R）。
- 情報提供のみを目的として送られたデータであり、3DS Serverが認証を要求していない（Transaction Status = I）。

注：アプリ方式の認証フローはSPC認証に対応しない。そのためTransaction Status = Sは許可されない。

**Seq 3.38 [Req 31]** 認証済みと判定した取引（Transaction Status = YまたはA）について、ACSは次を実施する。

- 支払認証（Message Category = 01-PA）：DSが定義するとおりに、ECI値とAuthentication Valueを生成し、AResに含めなければならない。
- 非支払認証（Message Category = 02-NPA）：ACSは、DSが定義するとおりにECI値とAuthentication Valueを生成してAResに含めてもよい。また、当該DSが定義する適切なTransaction Status Reasonコード値を割り当て、AResに含めてもよい。

注：ECI Indicator／Authentication Value、Transaction Status Reason値、またはその両方をAResに含めるかは、個々のDSが定義する。

**Seq 3.39 [Req 32]** チャレンジが必要と判定した場合（Transaction Status = C）、ACSは、AReqで受信したDevice Channel、Device Rendering Options Supported、SDK Maximum Timeout、およびSDK Typeなどに基づき、3DS SDKが許容可能なチャレンジ方法に対応しているかを判定する。ACSは次を実施する。

a. チャレンジ用にTransaction Status = Cを設定する。

b. ACS Rendering Typeを設定する。

c. ACSと3DS SDKの間のセキュアな通信経路を設定する（6.2.3.2節で定義）。

注1：この動作における判断処理は、本仕様の対象外である。

注2：認証試行（Attempts）への対応は、各DSが決定する。
