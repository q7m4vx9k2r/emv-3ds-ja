# PDF 153ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

DS：

**Seq 5.63 [Req 233]** ACSへの最初のTCP/IP接続とTLSハンドシェイクを完了できない場合、直ちに再試行するか、利用できれば代替ACSを試さなければならない。2回目も失敗した場合、DSは次のいずれかを3DS Serverに送信しなければならない。

- 取引を完了させるための、Error Component = D、Error Code = 405のErrorメッセージ（A.9節で定義）。
- 個々のDSが定義する適切な応答をTransaction Statusに設定したARes（表B.2で定義）。

注：DSは複数のACS URLを管理してもよい。最初のURLが利用できない場合、代替URLのいずれかへの接続を試みる。

**Seq 5.64 [Req 424]** ACSへの接続試行がすべて失敗した場合、DSは、Error Component = D、Error Code = 405のErrorメッセージ（A.9節で定義）をACSに送ってもよい。

**Seq 5.65 [Req 234]** DSは、TLSハンドシェイクが完了し、処理のためにAReq全体をACSに送信した時点から、該当するDS要件で定義するACSのタイムアウト値を設定しなければならない。

**Seq 5.66 [Req 235]** 読取りタイムアウト満了前にACSからAResを受信しない場合、DSは次のいずれかを送信しなければならない。

- 取引を完了させるための、Error Component = D、Error Code = 402のErrorメッセージ（A.9節で定義）を3DS Serverに送信する。
- 個々のDSが定義する適切な応答をTransaction Statusに設定したARes（表B.2で定義）を3DS Serverに送信する。その後、取引を完了させるため、Error Component = D、Error Code = 402のErrorメッセージ（A.9節で定義）をACSに送信する。

CReq／CResの読取りタイムアウトは次のとおり処理する。

3DS SDK：

**Seq 5.67 [Req 236]** ACSへの最初の接続とTLSハンドシェイクを完了できない場合、直ちに再試行しなければならない。2回目も失敗した場合、取引を完了させるため3DS Requestor Appにエラーを報告しなければならない。

**Seq 5.68 [Req 237]** TLSハンドシェイクが完了し、処理のためにCReq全体をACSに送信した時点から、タイムアウトを10秒に設定しなければならない。

**Seq 5.69 [Req 239]** 10秒の読取りタイムアウト満了前にACSがCResで応答しない場合、3DS SDKは3-D Secure処理を終了する。Error Component = C、Error Code = 402のErrorメッセージ（A.9節で定義）をACSに渡し、呼出元アプリにもErrorメッセージを渡して、取引を終了する。

**Seq 5.70 [Req 312]** TLSハンドシェイクが完了し、処理のために最初のCReqをACSに送信した時点から、SDK Maximum Timeout値を設定しなければならない。

SDK Maximum Timeout満了前にACSがFinal CResで応答しない場合、3DS SDKは3-D Secure処理を終了する。Error Component = C、Error Code = 402のErrorメッセージ（A.9節で定義）をACSに渡し、呼出元アプリにもErrorメッセージを渡して、取引を終了する。
