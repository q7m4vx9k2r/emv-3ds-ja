# PDF 74ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

[目次](../../index.md) · [英語原文](../../en/pages/074.md) · [前ページ](./073.md) · [次ページ](./075.md)

**Seq 3.143 [Req 105]** AReqのCardholder Account Numberを使い、そのカード会員の認証が利用可能か、または完了可能かを判定する。

Cardholder Account Numberの認証が利用できない場合、ACSは3DS Serverに、個々のDSが定義する適切な応答をTransaction StatusとTransaction Status Reasonコードに設定したARes（表B.2で定義）を返し、処理を終了する。

ACSには、次の実施を推奨する。

**Seq 3.144 [Req 106]** [Req 107]で定義する取引の処置を評価する際、AReqで受信した3DS Requestor Challenge Indicator、3DS Requestor Authentication Indicator、および3DS Requestor Decoupled Request Indicatorの値を使用する。

ACSは、次を実施しなければならない。

**Seq 3.145 [Req 107]** AReqで受信した値を評価し、取引〔注3〕が次のいずれに該当するかを判定する。

- 認証済み（Transaction Status = Y）。
- 認証の完了にカード会員のチャレンジが必要（Transaction Status = C）。
- Decoupled Authenticationによるカード会員のチャレンジが必要（Transaction Status = D）。
- 未認証（Transaction Status = N）。
- 未認証だが、認証試行の証明（Authentication Value）を生成済み（Transaction Status = A）〔注4〕。
- 技術上またはその他の問題により認証できず、未認証（Transaction Status = U）。
- イシュアが認証を拒否し、オーソリゼーションを試みないよう要求しているため未認証（Transaction Status = R）。
- 情報提供のみを目的として送られたデータであり、3DS Serverが認証を要求していない（Transaction Status = I）。
- SPC認証が必要（Transaction Status = S）。詳細は3.5.1節を参照すること。

**Seq 3.146 [Req 108]** 認証済みと判定した取引（Transaction Status = YまたはA）について、ACSは次を実施する。

- 支払認証（Message Category = 01）：DSが定義するとおりに、ECI値とAuthentication Valueを生成し、AResに含めなければならない。
- 非支払認証（Message Category = 02）：ACSは、当該決済システムが定義するとおりにECI値とAuthentication Valueを生成し、AResに含めてもよい。

注3：この動作における判断処理は、本仕様の対象外である。

注4：認証試行（Attempts）への対応は、各DSが決定する。
