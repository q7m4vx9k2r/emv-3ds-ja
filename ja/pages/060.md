# PDF 60ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

#### 手順13：ACS

ACSは、次を実施しなければならない。

**Seq 3.64 [Req 51]** 表B.4で定義するとおりにCResを整形する。

**Seq 3.65 [Req 52]** 6.2.4.4節で定義するとおりにCResの内容を保護する。

内容の保護に失敗した場合、ACSは3-D Secure処理を終了する。

**Seq 3.66 [Req 53]** 3DS SDKとの初回の対話には[Req 44]で、継続する対話には[Req 56]で確立したセキュアな接続を使って、CResを3DS SDKに送信する。

#### 手順14：3DS SDK

3DS SDKは、次を実施しなければならない。

**Seq 3.67 [Req 54]** ACSからCResまたはErrorメッセージを受信し、5.9.7節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS SDKは処理を終了する。

**Seq 3.68 [Req 55]** 選択されたACS UI Typeと設定されたデータ要素に基づいてUIを表示する。UIの詳細は、適用される3DS SDK仕様の4.2節を参照すること。OOB認証（ACS UI Type = 04または06）については3.2節を参照すること。

Native UI用のCResに、外部サーバからデータを取得するよう3DS SDKに指示するURLが含まれる場合（すなわちNative UI用のIssuer ImageやPayment System Image）、6.1.4.1節で定義する追加のセキュアな接続を外部サーバとの間に確立し、データを取得してUI内に表示する。

セキュアな接続を確立できない場合、3DS SDKはチャレンジを続行し、提供されたその他すべての必須・任意のUIデータ要素を表示する。ACSにErrorメッセージは送信しない。

#### 手順15：カード会員と3DS SDKの対話

カード会員がUIを操作する（例えばデータを入力し、Submitを選択する）。

**Seq 3.69 [Req 59]** 手順12〜15の処理中にカード会員がチャレンジを放棄した場合、3DS SDKはCReqのChallenge Cancelation Indicatorに適切な値を設定する。

注：ACS UI Type = 04または06については、3.2節のOOB認証要件を参照すること。

#### 手順16：3DS SDK

3DS SDKは、次を実施しなければならない。

**Seq 3.70 [Req 56]** 6.1.4.1節で定義するとおりにACSとのセキュアな接続を確立する。

**Seq 3.71 [Req 57]** 表B.3で定義するとおりにCReqを整形し、6.2.4.1節で定義するとおりに内容を保護する。

内容の保護に失敗した場合、3DS SDKは3DS Requestor Appにエラーを報告し、3-D Secure処理を終了する。

**Seq 3.72 [Req 58]** [Req 56]で確立したセキュアな接続を使って1つのCReqをACSに送信する。次のCReqを送信する前に、ACSからのCRes応答を待つ。
