また、非支払認証では、当該DSが定義する適切なTransaction Status Reason値を割り当て、AResに含めてもよい。

注：ECI Indicator／Authentication Value、Transaction Status Reason値、またはその両方をAResに含めるかは、個々のDSが定義する。

**Seq 3.147 [Req 109]** チャレンジが必要と判定した場合（Transaction Status = C）、ACSは、AReqで受信した3DS Requestor Challenge Indicatorを考慮し、3DS Serverが許容可能なチャレンジ方法に対応しているかを判定する。ACSは次を実施する。

a. チャレンジ用にTransaction Status = Cを設定する。

b. ブラウザとACSの間の接続に使用するACS URLフィールドをAResに設定する。

c. 後続のRReq処理のために3DS Server Transaction ID、DS URL、およびDS Transaction IDを保存する。

**Seq 3.148 [Req 325]** Decoupled Authenticationのチャレンジが必要と判定され（Transaction Status = D）、3DS Requestor Decoupled Request Indicator = YまたはBの場合、ACSは、AReqで受信した3DS Requestor Decoupled Max Timeなどに基づき、許容可能なチャレンジ方法に自身が対応しているかを判定する。ACSは次を実施する。

a. Decoupled Authentication用にTransaction Status = Dを設定する。

b. ACS Decoupled Confirmation Indicator = Yを設定する。

c. 後続のRReq処理のために3DS Server Transaction IDとDS Transaction IDを保存する。

**Seq 3.149 [Req 110]** 表B.2で定義するとおりにAResの整形を完了する。

**Seq 3.150 [Req 111]** [Req 100]で確立したセキュアな接続を使って、AResをDSに送信する。

**Seq 3.151 [Req 326]** Decoupled Authentication取引（Transaction Status = D）について、次の非同期処理を行う。

a. 3DS Requestor Decoupled Max Timeに対するタイマーを開始する。

b. カード会員を認証する。認証判断の方法は本仕様の対象外である。ただしACSの目標は、3DS Requestor Decoupled Max Timeが満了する前にカード会員認証を完了することである。
