# PDF 58ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

[目次](../../index.md) · [英語原文](../../en/pages/058.md) · [前ページ](./057.md) · [次ページ](./059.md)

**Seq 3.47 [Req 421]** ACSに代わってDSがAResを生成する場合（例えば、DSがTransaction Status = Aを返す場合）、ACS Reference NumberにDS Reference Numberを、ACS Transaction IDにDS Transaction IDを設定する。また、AResで必要となるその他のACSデータ要素をすべて、DSの機能に応じて設定する。

**Seq 3.48 [Req 37]** [Req 12]で確立したセキュアな接続を使って、ACSから受信したAResを3DS Serverに送信する。

#### 手順9：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.49 [Req 38]** DSからAResまたはErrorメッセージを受信し、5.9.4節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS Serverは処理を終了する。

**Seq 3.50 [Req 39]** 認証済み取引（Transaction Status = YまたはA）について、次を実施する。

a. 支払認証（Message Category = 01-PA）の場合、ACSが生成したTransaction Status、ECI値、およびAuthentication Valueが、オーソリゼーション処理に提供されるようにする。

b. AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信する。

c. [Req 79]に進む。

**Seq 3.51 [Req 40]** チャレンジを伴う取引（Transaction Status = C）について、3DS Requestor Challenge Indicator、ACS Challenge Mandated Indicator、およびACS Rendering Typeなどに基づき、要求されたチャレンジを実施するかを評価する。

- 3DS Requestorがチャレンジを受け入れる場合：AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信し、手順10に進む。
- 3DS Requestorが要求されたチャレンジを実施せずに続行する場合：DSからRReqを受信し、5.9.9節で定義するとおりに検証する。メッセージにエラーがある場合、3DS Serverは処理を終了する。表B.9で定義するとおりにRResを整形し、DSに送信する。それ以降の処理は3-D Secure処理の対象外である。3DS Serverは[Req 79]に進んでもよく、3-D Secure処理を終了する。

**Seq 3.52 [Req 41]** 未認証取引（Transaction Status = N、U、またはR）について、次を実施する。

a. AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信する。

b. [Req 79]に進む。

**Seq 3.53 [Req 323]** Decoupled Authentication取引（Transaction Status = D）について、AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信する。

**Seq 3.54 [Req 355]** Cardholder Information Textを3DS Requestor Environmentに伝える。3DS Requestorは、A.20節に示すとおりに、受信したCardholder Information Textをカード会員に表示する。
