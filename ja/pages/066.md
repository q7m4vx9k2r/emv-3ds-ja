カード会員が認証していないとACSが判断した場合、別のCResを通じてカード会員向けの指示を更新できる。OOB認証の認証判断の方法は本仕様の対象外である。ただしACSは、手順18より前にOOB認証の結果を利用できる必要がある。

注：本節で定義するOOB認証とDecoupled Authenticationは別の認証フローである。3.2節の要件は、ACS UI Type 04および06に固有の追加フローと要件を記載する。

### 3.2.1 OOBの要件

本節では、OOBフローの追加要件を定義する。

#### 手順15：カード会員と3DS SDKの対話

3DS SDKは、次を実施しなければならない。

**Seq 3.100 [Req 399]** ACS UI Type = 04の場合、カード会員がOOB Continuation Labelを持つボタンを選択したとき、OOB Continuation Indicator = 01を設定する。

**Seq 3.101 [Req 400]** ACS UI Type = 04または06の場合、3DS Requestor Appがフォアグラウンドになったとき（例えばカード会員が同アプリに戻ったとき）、OOB Continuation Indicator = 02を設定する。カード会員によるUI操作を必要とせず、アプリ方式のフローの手順16に自動的に進む（CReqをACSに送信する）。

### 3.2.2 OOBの自動切替機能

本仕様は、OOB認証について次の自動切替機能を定義する。

- OOB App URL（CRes内）：カード会員が制御の移行を選択したとき、3DS SDKがOOB Authentication Appに自動的に切り替えるために使用する。
- 3DS Requestor App URL（CReq内）：OOB Authentication Appがカード会員との対話を終了したとき、同アプリが3DS Requestor Appに制御を自動的に移すために使用する。

2つのアプリ間の自動切替が失敗するエラーの状況に対応するため、3DS Requestor Appがフォアグラウンドに戻った時点で、3DS SDKはCReqを自動送信する。これにより、ACSが認証試行の最新状況を把握できる。その後ACSは、OOB Authentication Appによる認証が行われたかどうかに応じて、次の認証手順を選択してもよい。

OOB Authentication Appと3DS Requestor Appが別の端末上にある場合、自動切替はできず、カード会員がもう一方の端末のアプリに手動で切り替える必要がある。

自動切替機能を使用する場合、次の追加要件が適用される。

#### 手順13：ACS

[Req 51]より前に、ACSはOOB認証用のCResを追加で準備する。OOB App URL機能を使用する場合、ACSは次を実施しなければならない。

**Seq 3.102 [Req 401]** ACS UI Type = 04または06の場合、OOB App URLに、OOB Authentication Appのインストール時に使用したURL値を設定する。
