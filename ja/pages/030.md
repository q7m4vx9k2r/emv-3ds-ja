### 表1.3：定義（続き）

| 用語 | 定義 |
| --- | --- |
| Results Response（RRes）Message | RReqの受領を確認するため、3DS ServerがDSを経由してACSへ送るメッセージ。 |
| Secret key（共通秘密鍵） | DESなどの対称暗号アルゴリズムで使う鍵。公開されるとシステムの安全性が損なわれる。 |
| Secure Payment Confirmation | ブラウザーのPayment Request APIから開始する決済を、安全に確認するFIDOベース認証。詳細はw3.orgを参照。 |
| Token Service Provider | トークンプログラムにより、登録済みToken RequestorにPayment Tokenを提供する権限を与えられた、決済トークン化エコシステムの役割。『EMV® Payment Tokenisation Specification - Technical Framework』参照。 |
| Transport Layer Security（TLS） | インターネットなどの公開ネットワークで、情報を機密に伝送するためIETFが開発した暗号プロトコル。RFCは表1.1参照。 |
| Trust List | 本仕様では、カード会員が3DS Requestorを信頼済み受取人一覧に登録できるようにするプロセス。 |
| Uniform Resource Locator（URL） | World Wide Webのページのアドレス方式。通常 `http://www.example.com` または `https://www.example.com` の形式。 |
| Universal App Link | インストール済みの特定モバイルアプリを開く、OS登録済みHTTPSリンク。実装はプラットフォーム固有。Android：https://developer.android.com/training/app-links 、iOS：https://developer.apple.com/ios/universal-links |
| Universally Unique Identifier（UUID） | ソフトウェア構築で使う識別子標準。標準形は32桁の小文字16進数字を、ハイフンで区切った8-4-4-4-12の5群で表示する。数字・文字32字とハイフン4字の計36字。RFCは表1.1参照。 |
| Validate | 表A.1の各データ要素の存在・形式要件に従い、メッセージを検査するプロセス。5.1.6節に詳細を示す。5.9節も参照。 |
| Verify | 6.2節で定義する暗号技術によるメッセージ検査。5.9節も参照。 |
| Wallet | Digital walletを参照。 |
| WebAuthn | Webアプリケーションが強固なユーザー認証のため、強固で証明付き・スコープ付きの公開鍵ベース認証情報を生成・利用するAPIを定める。https://www.w3.org/TR/webauthn-2/ 参照。 |
| X.509 | RFC 4158で定義する証明書形式。 |
