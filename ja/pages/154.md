### 5.5.2.2 RReq／RResのタイムアウト

RReq／RResの読取りタイムアウトは次のとおり処理する。

ACS：

**Seq 5.71 [Req 240]** DSへの最初の接続とTLSハンドシェイクを完了できない場合、直ちに再試行しなければならない。2回目も失敗した場合、10秒待ってDSへの接続を再試行し、Transaction Status = Uでメッセージが配信されるまで繰り返す。

**Seq 5.72 [Req 241]** TLSハンドシェイクが完了し、処理のためにRReq全体をDSに送信した時点から、タイムアウトを5秒に設定しなければならない。

**Seq 5.73 [Req 242]** 読取りタイムアウト満了前にDSがRResまたはErrorメッセージで応答しない場合、ACSは、Error Component = A、Error Code = 402のErrorメッセージ（A.9節で定義）をDSに返さなければならない。既定値は5秒だが、DSがより大きい代替値を指定してもよい。

DS：

**Seq 5.74 [Req 243]** 3DS Serverへの最初の接続とTLSハンドシェイクを完了できない場合、直ちに再試行しなければならない。2回目も失敗した場合、取引を完了させるため、Error Component = D、Error Code = 405のErrorメッセージ（A.9節で定義）をACSに送信しなければならない。また、Error Component = D、Error Code = 405のErrorメッセージを3DS Serverに送ってもよく、3-D Secure処理を終了する。

**Seq 5.75 [Req 244]** TLSハンドシェイクが完了し、処理のためにRReq全体を3DS Server URLへ送信した時点から、タイムアウト値を設定しなければならない。既定値は3秒だが、DSがより大きい代替値を指定してもよい。

注：DSは、[Req 242]のタイムアウト値が[Req 244]の値より大きいことを確実にして設定する。

**Seq 5.76 [Req 245]** 3秒（またはDSの代替値）の読取りタイムアウト満了前に3DS ServerがRResを送信しない場合、取引を完了させるため、Error Component = D、Error Code = 402のErrorメッセージ（A.9節で定義）をACSに送信しなければならない。また、Error Component = D、Error Code = 402のErrorメッセージを3DS Serverに送ってもよく、3-D Secure処理を終了する。

### 5.6 PReq／PResのメッセージ処理要件

3DS ServerはPReq／PResを使い、利用可能なACSとDSが対応するProtocol Version Number、および3DS Method呼出し用URLをキャッシュする。データはDSの設定に従ってカード範囲ごとに整理される。ACSとDSが対応するプロトコルバージョン情報は、すべての3DSフローで使用できる。

3DS Serverは、PRes内でCard Range Dataを受信するか、DSが任意に対応する場合は、そのデータを含むファイルのダウンロードURLを受信する選択肢を持つ。
