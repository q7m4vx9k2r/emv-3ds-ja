AResのデータ要素が検証に失敗した場合、3DS Serverは次を行う。

- DSに、Error Component = S、Error Code = 203のErrorメッセージ（A.9節で定義）を返す。
- 特定の取引を識別できる場合、3DS Requestor Environmentにエラーの発生を通知する。

必須データ要素が欠ける場合：

- DSに、Error Component = S、Error Code = 201のErrorメッセージ（A.9節で定義）を返す。
- 特定の取引を識別できる場合、3DS Requestor Environmentにエラーの発生を通知する。

それ以外ではメッセージにエラーはない。

Errorメッセージの場合、特定の取引を識別できれば、3DS Requestor Environmentにエラーの発生を通知する。

注：アプリ方式の実装では、3DS Requestor Environmentが3DS SDKにエラーを通知することを想定している。

### 5.9.5 ACSによるCReqのエラー処理：01-APP

ACSは、CReqまたはErrorメッセージの検証を次のとおり処理する。

6.2.4.3節に従って正しく暗号学的検証・復号ができない、または認識できないメッセージの場合：

- [Req 44]のセキュアな接続を使い、3DS SDKにError Component = A、Error Code = 101（認識できない）または302（暗号学的検証・復号の失敗）のErrorメッセージ（A.9節で定義）を返す。
- 特定の取引を識別できる場合、DSに5.9.5.1節のRReqを送る。

正しく暗号学的検証・復号・認識ができたCReqは、Device Channel = 01-APPに従い、表B.3と5.1.7節で定義する検証を行う。

- 存在するデータ要素が検証に失敗した場合、[Req 44]の接続を使い、3DS SDKにError Component = A、Error Code = 203のErrorメッセージ（A.9節で定義）を返す。特定の取引を識別できれば、DSに5.9.5.1節のRReqを送る。
- 必須データ要素が欠ける場合、[Req 44]の接続を使い、3DS SDKにError Component = A、Error Code = 201のErrorメッセージ（A.9節で定義）を返す。特定の取引を識別できれば、DSに5.9.5.1節のRReqを送る。
- AReqで受信したSDK Type = 02、かつCReqがA128GCMで保護されていない場合（6.2.4.3節の`enc`がA128GCMでない場合）、ACSは次ページの処理を行う。
