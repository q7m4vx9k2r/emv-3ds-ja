[Req 291]で判定する取引の状態は次のとおりである。

- 認証済み（Transaction Status = Y）。
- Decoupled Authenticationによるカード会員のチャレンジが必要（Transaction Status = D）。
- 未認証（Transaction Status = N）。
- 未認証だが、認証試行の証明（Authentication Value）を生成済み（Transaction Status = A）〔注6〕。
- 技術上またはその他の問題により認証できず、未認証（Transaction Status = U）。
- イシュアが認証を拒否し、オーソリゼーションを試みないよう要求しているため未認証（Transaction Status = R）。
- 情報提供のみを目的とするデータであり、3DS Serverが認証を要求していない（Transaction Status = I）。

**Seq 3.217 [Req 292]** 認証済みと判定した取引（Transaction Status = YまたはA）について、ACSは次を実施する。

- 支払認証（Message Category = 01-PA）：当該決済システムが定義するとおりに、ECI値とAuthentication Valueを生成し、AResに含めなければならない。
- 非支払認証（Message Category = 02-NPA）：当該決済システムが定義するとおりにECI値とAuthentication Valueを生成し、AResに含めてもよい。また、当該DSが定義する適切なTransaction Status Reason値を割り当て、AResに含めてもよい。
- ECI Indicator／Authentication Value、Transaction Status Reason値、またはその両方をAResに含めるかは、個々のDSが定義する。

**Seq 3.218 [Req 328]** Decoupled Authenticationのチャレンジが必要と判定した場合（Transaction Status = D）、ACSは、AReqで受信した3DS Requestor Decoupled Max Timeなどに基づき、許容可能なチャレンジ方法に自身が対応しているかを判定する。ACSは次を実施する。

a. Transaction Status = D（Decoupled Authentication）を設定する。

b. ACS Decoupled Confirmation Indicator = Yを設定する。

c. 後続のRReq処理のために3DS Server Transaction IDとDS Transaction IDを保存する。

**Seq 3.219 [Req 293]** 表B.2で定義するとおりにAResの整形を完了する。

**Seq 3.220 [Req 294]** [Req 285]で確立したセキュアな接続を使って、AResをDSに送信する。
