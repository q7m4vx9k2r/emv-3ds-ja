- メッセージが無効であり、例外のシナリオを処理する。

本節では、メッセージが無効な場合、またはErrorメッセージを受信した場合の処理だけを説明する。3-D Secure取引フローに沿い、特定のメッセージを受信する各構成要素の組合せごとに節を設ける。有効なメッセージの処理と業務ロジックに基づく例外は、第3章で説明する。

### 5.9.1 DSによるAReqのエラー処理

DSは、AReqの検証を次のとおり処理する。以下のErrorメッセージはA.9節で定義する。

- メッセージを認識できない場合：Error Component = D、Error Code = 101を3DS Serverに返す。
- AReqの場合：Device Channelの内容に従い、表B.1と5.1.7節で定義する検証を行う。存在するデータ要素が検証に失敗した場合、Error Component = D、Error Code = 203を3DS Serverに返す。必須データ要素が欠ける場合、Error Component = D、Error Code = 201を3DS Serverに返す。それ以外ではメッセージにエラーはない。

### 5.9.2 ACSによるAReqのエラー処理

ACSは、AReqの検証を次のとおり処理する。以下のErrorメッセージはA.9節で定義する。

- メッセージを認識できない場合：Error Component = A、Error Code = 101をDSに返す。
- AReqの場合：Device Channelの内容に従い、表B.1と5.1.7節で定義する検証を行う。存在するデータ要素が検証に失敗した場合、Error Component = A、Error Code = 203をDSに返す。必須データ要素が欠ける場合、Error Component = A、Error Code = 201をDSに返す。それ以外ではメッセージにエラーはない。

### 5.9.3 DSによるAResのエラー処理

DSは、AResまたはErrorメッセージの検証を次のとおり処理する。

認識できないメッセージの場合：

- ACSに、Error Component = D、Error Code = 101のErrorメッセージ（A.9節で定義）を返す。
- 3DS Serverに、5.9.3.1節で定義するメッセージを送信する。
