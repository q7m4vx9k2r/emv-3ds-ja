#### 手順1：3DS Requestor

3DS Requestorは、3DS Serverが組み立てるAReqの情報を収集する責任を持つ。2.1.1節で紹介したとおり、本仕様は情報を収集する特定の構成要素を指定せず、AReqを構築する際に3DS Serverが情報を利用できることのみを求める。情報には、次のものを含めることができる。

- Cardholder Account Information
- Merchant Risk Indicator
- 3DS Requestor Prior Transaction Authentication Information
- 支払情報
- 非支払情報
- カード会員情報

これらの情報を3DS Serverが利用できるようにする。

3DS Serverは、次を実施しなければならない。

**Seq 3.193 [Req 271]** 3DS Requestorと3DS Serverが別の構成要素である場合、両方のサーバの相互認証を行い、両構成要素間で転送するデータが決済システムのセキュリティ要件を満たす水準で保護されるようにする。

- 要求どおりに通信を確立できない場合、3DS Serverは3-D Secure処理を終了する。
- 3DS Requestor Environment内の通信経路のために、妥当な時間内で3DS Serverが情報を受信できない場合、そのことを3DS Requestorに通知し、3-D Secure処理を終了しなければならない。

#### 手順2：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.194 [Req 272]** 3DS Requestor ID、3DS Server Reference Number、および条件付きでAcquirer BINを取得する。

**Seq 3.195 [Req 302]** 3DS Server Transaction IDを生成する。

**Seq 3.196 [Req 273]** 3DS Requestor Environment内の構成要素が収集した、AReqに必要な情報（表B.1で定義）が利用可能であることを確認する。

必要な情報を利用できない場合、3DS Serverは3-D Secure処理を終了する。

**Seq 3.197 [Req 274]** ISO 7812で定義されるBINと、任意のその他のCardholder Account Informationに基づき、認証取引の送信先となるDSを判定する。

**Seq 3.198 [Req 275]** 6.1.2.1節で定義するとおりにDSとのセキュアな接続を確立する。

DSとの接続を確立できない場合、3DS Serverは3-D Secure処理を終了する。

**Seq 3.199 [Req 423]** PResから取得したACS Protocol VersionsおよびDS Protocol Versionsのプロトコルバージョン一覧を使い、共通して対応する最高のMessage Version Numberを設定する。
