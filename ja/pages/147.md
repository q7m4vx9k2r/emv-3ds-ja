**Seq 5.15 [Req 320]** Message Version Numberは、3DSメッセージを開始する3-D Secure構成要素が設定する。各3-D Secure構成要素は、3-D Secure取引を通じてその値が変わらないことを検証しなければならない。検証エラーを特定した構成要素は、適切なError ComponentとError Code = 203を持つErrorメッセージ（A.9節で定義）を返さなければならない。

**[Req 311]** 3DS構成要素は、より低いすべての有効なProtocol Version（EMV Specification Bulletin 255でProtocol Version StatusがActive）に対応しなければならない。また、現在のバージョンの最新パッチに対応しなければならない。当該構成要素が対応する有効なMessage Version Numberを含む3-D Secureメッセージは、指定されたProtocol Versionの要件に従って処理しなければならない（EMV Specification Bulletin 255参照）。

### 5.1.5 データのバージョン番号

**Seq 5.16 [Req 396]** 3DS SDKは、3DS SDK Device Informationの最新のData Versionに対応しなければならない。

**Seq 5.17 [Req 397]** ACSは、3DS SDK Device Informationのすべての有効なData Versionに対応しなければならない。

注：EMV Specification Bulletin 255およびEMV 3-D Secure SDK—Device Informationを参照すること。

### 5.1.6 メッセージの解析

3-D Secureメッセージの受信側は、正しく処理できることを確実にするためメッセージを検証する。受信時に、次を検証しなければならない。

**Seq 5.18 [Req 196]** 附属書Aで定義する適用要件を満たすこと。

**Seq 5.19 [Req 197]** Message Typeフィールドに基づき、取引のコンテキストが受信側構成要素にとって有効であること。

**Seq 5.20 [Req 198]** RFC 7159で定義するJSONメッセージ、またはRFC 7516／7515で定義するJWE／JWSオブジェクト形式として正しく整形されていること。

**Seq 5.21 [Req 199]** Message Typeフィールドが受信側構成要素にとって有効であること。

受信側構成要素は、次のメッセージ種別を受信する。

**Seq 5.22 [Req 200]** 3DS SDKは、CResまたはErrorメッセージのみを受け付けなければならない。他の種別はエラーとして扱わなければならない。

**Seq 5.23 [Req 201]** 3DS Serverは、ARes、RReq、PRes、OReq、Errorメッセージのみを受け付けなければならない。他の種別はエラーとして扱わなければならない。

**Seq 5.24 [Req 202]** DSは、AReq、ARes、RReq、RRes、PReq、ORes、Errorメッセージのみを受け付けなければならない。他の種別はエラーとして扱わなければならない。

**Seq 5.25 [Req 203]** ACSは、AReq、CReq、RRes、OReq、Errorメッセージのみを受け付けなければならない。他の種別はエラーとして扱わなければならない。

**Seq 5.26 [Req 430]** 3DS Serverが1つの取引中に複数のRReqを受信した場合、Error Code = 312を返さなければならない。
