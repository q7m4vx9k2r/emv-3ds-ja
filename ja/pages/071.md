2.1.1節で紹介したとおり、本仕様は情報を収集する特定の構成要素を指定せず、AReqを構築する際に3DS Serverが情報を利用できることのみを求める。情報には、次のものを含めることができる。

- Cardholder Account Information
- Merchant Risk Indicator
- 3DS Requestor Authentication Information
- 3DS Requestor Prior Transaction Authentication Information
- 支払情報
- 非支払情報
- カード会員情報

これらの情報を3DS Serverが利用できるようにする。

3DS Serverは、次を実施しなければならない。

**Seq 3.119 [Req 86]** クライアント（ブラウザ）とサーバ（3DS Requestor）の通信が、6.1.1節で定義する、サーバ認証を行うTLSセッションを使って確立されていることを確実にする。

- 要求どおりに通信を確立できない場合、3DS Serverは3-D Secure処理を終了する。
- 3DS Requestor Environment内の通信経路のために、妥当な時間内で3DS Serverが情報を受信できない場合は、ブラウザを通じてそのことをカード会員に通知し、3-D Secure処理を終了する必要がある。

**Seq 3.120 [Req 301]** 3DS Requestorと3DS Serverが別の構成要素である場合、両方のサーバの相互認証を行い、両構成要素間で転送するデータが決済システムのセキュリティ要件を満たす水準で保護されるようにする。

要求どおりに通信を確立できない場合、3DS Serverは3-D Secure処理を終了する。

#### 手順6：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.121 [Req 87]** 3DS Requestor ID、3DS Server Reference Number、および条件付きでAcquirer BINを取得する。

**Seq 3.122 [Req 88]** 3DS Requestor Environment内の構成要素が収集した、AReqに必要な情報（表B.1で定義）が利用可能であることを確認する。

必要な情報を利用できない場合、3DS Serverは3-D Secure処理を終了する。

**Seq 3.123 [Req 441]** 3DS Requestorが過去10分以内に3DS Methodを実行したことを確実にする。それ以外の場合、3DS Requestorは5.8.1節で定義するとおりに3DS Methodを再実行する。

**Seq 3.124 [Req 89]** ISO 7812で定義されるBINと、任意のその他のCardholder Account Informationに基づき、認証取引の送信先となるDSを判定する。

**Seq 3.125 [Req 90]** 6.1.2.1節で定義するとおりにDSとのセキュアな接続を確立する。
