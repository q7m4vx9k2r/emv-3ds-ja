#### 手順18：ACS

ACSは、すべてのチャレンジフロー取引（AResのTransaction Status = C）に対して、またDecoupled Authentication取引（AResのTransaction Status = D）では[Req 322].bの認証が完了するか[Req 322].aのタイマーが満了した時点で、次を実施しなければならない。

**Seq 3.77 [Req 462]** チャレンジフロー（AResのTransaction Status = C）で、3DS Requestor Decoupled Request Indicator = FまたはB、かつACSがDecoupled Authentication Fallbackを必要と判断した場合、次を設定する。

- Transaction Status = D。
- Transaction Status Reason = 29または30。

**Seq 3.78 [Req 62]** 表B.8で定義するとおりにRReqを整形する。

**Seq 3.79 [Req 63]** 6.1.3.2節で定義するとおりにDSとのセキュアな接続を確立する。

**Seq 3.80 [Req 64]** 手順16および17の処理中にカード会員がチャレンジを放棄した場合、またはACSが3DS SDKから放棄を示すCReq（[Req 60]で定義）を受信した場合、ACSはCResのChallenge Completion Indicator = Yを設定し、RReqのChallenge Cancelation Indicatorに適切な値を設定する。具体的な値は附属書Aを参照すること。

**Seq 3.81 [Req 65]** [Req 63]で確立したセキュアな接続を使って、RReqをDSに送信する。

**Seq 3.82 [Req 66]** Transaction Status = CまたはDの各AResに対して、1つのRReqをDSに送信することを確実にする。

**Seq 3.83 [Req 345]** Decoupled Authentication取引について、次を確実にする。

- 成否にかかわらず、認証結果を取得したら直ちにRReqを送信する。
- 3DS Requestor Decoupled Max Timeが満了した場合、1時間の猶予期間を設けて、認証結果を含まないRReq（Transaction Status = U）を送信する。

注：Transaction Status = UのRReqには、Transaction Status Reason = 24または26、およびChallenge Cancelation Indicator = 03を含めることを推奨する。

#### 手順19：DS

DSは、次を実施しなければならない。

**Seq 3.84 [Req 67]** ACSからRReqを受信し、5.9.8節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.85 [Req 68]** AReqから取得し[Req 22]で保存した3DS Server URLを使い、6.1.2.2節で定義するとおりに3DS Serverとのセキュアな接続を確立する。

**Seq 3.86 [Req 69]** [Req 68]で確立したセキュアな接続を使って、RReqを3DS Serverに送信する。
