[Req 123]の続き：認証に失敗した場合、認証が未完了の場合、またはカード会員が認証の取消しを選択した場合、ACSはInteraction Counterを増分し、ACSのチャレンジ最大回数と比較する。

Interaction Counter ≥ ACSのチャレンジ最大回数、認証に失敗した場合、またはカード会員が認証の取消しを選択した場合、ACSは次を実施する。

- Transaction Status = Nを設定する。
- Transaction Status Reason = 19を設定する。
- 当該DSが定義するECI値を設定する。
- 手順16に進む。

それ以外で、Interaction Counter < ACSのチャレンジ最大回数、または認証が未完了の場合、ACSは次を実施する。

- 選択されたチャレンジ方法とACS UI Typeに従い、消費者端末にチャレンジを再表示するために必要な情報を取得する。
- HTML、JavaScriptなどを含めることができる認証用UI（ACS UI）を、カード会員のブラウザ向けに準備する。
- 手順12に進む。

ACSが判定するまで、HTMLをやり取りする処理を繰り返す。

#### 手順16：ACS

ACSは、すべてのチャレンジフロー取引（AResのTransaction Status = C）に対して、またDecoupled Authentication取引（AResのTransaction Status = D）では[Req 326].bの認証が完了するか[Req 326].aのタイマーが満了した時点で、次を実施しなければならない。

**Seq 3.171 [Req 465]** チャレンジフロー（AResのTransaction Status = C）で、3DS Requestor Decoupled Request Indicator = FまたはB、かつACSがDecoupled Authentication Fallbackを必要と判断した場合、次を設定する。

- Transaction Status = D。
- Transaction Status Reason = 29または30。

**Seq 3.172 [Req 124]** 表B.8で定義するとおりにRReqを整形する。

**Seq 3.173 [Req 125]** 6.1.3.2節で定義するとおりにDSとのセキュアな接続を確立する。

**Seq 3.174 [Req 126]** 手順12〜14の処理中にカード会員がチャレンジを放棄した場合、ACSはRReqのChallenge Cancelation Indicatorに適切な値を設定する。具体的な値は附属書Aを参照すること。

**Seq 3.175 [Req 127]** RReqをDSに送信する。
