### 5.9.5.1 メッセージにエラーがある場合

ACSは6.1.3.2節に従ってDSとのセキュアな接続を確立し、その接続でTransaction Status = U、Challenge Cancelation Indicator = 10のRReq（表B.8で定義）をDSに送る。

### 5.9.6 ACSによるCReqのエラー処理：02-BRW

ACSは、CReqの検証を次のとおり処理する。

- 認識できないメッセージの場合、特定の取引を識別できれば、DSに5.9.5.1節のRReqを送る。
- 複数のCReqを受信した場合、最初のCReqとデータ要素が同じかを検証する。
- いずれかの要素が異なる場合、DSに5.9.5.1節のRReqを送り、ブラウザ経由でError Component = A、Error Code = 305のErrorメッセージ（A.9節で定義）を返す。
- 後続のCReqが最初のCReqと同じでもACSがチャレンジを進めない場合、DSに5.9.5.1節のRReqを送り、ブラウザ経由でNotification URLへError Component = A、Error Code = 314のErrorメッセージを返す。
- ACSがRReqを送った後に後続のCReqを受信した場合、ブラウザ経由でNotification URLへError Component = A、Error Code = 315のErrorメッセージを返す。

CReqの場合、ACSはDevice Channel = 02-BRWに従い、表B.3と5.1.7節で定義する検証を行う。データ要素が検証に失敗した場合の処理は次ページに続く。
