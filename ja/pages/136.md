ACSは、完了するまでチャレンジメッセージのサイクルを継続する。完了したかどうかは、CResのChallenge Completion Indicatorデータ要素を通じて3DS SDKに伝える。3DS SDKに送信するCResには、イシュア／ACSが設計したとおりに画面を描画するため、ACS HTMLデータ要素を含める。

### 4.2.7.3 3DS SDK

3DS SDKは、次を実施しなければならない。

**Seq 4.56 [Req 166]** ACSからCResを受信したとき、ACS HTMLデータ要素からHTMLデータを取り出し、要求された内容を表示する。

**Seq 4.57 [Req 167]** Webビューによる外部リソースの取得要求をすべてインターセプトし、遮断する。

**Seq 4.58 [Req 168]** 3DS Requestorのヘッダーを含むビューを構築し、HTML UIテンプレートで指定するとおり、ACS HTMLを含むビューの上部に配置する。

**Seq 4.59 [Req 169]** Webビュー（WebView、View Controllerなど）を使ってカード会員にUIを表示する。

**Seq 4.60 [Req 170]** Cancelアクションなど、カード会員の操作を処理する。

**Seq 4.61 [Req 171]** Cancelアクションが選択されたとき、3DS Requestor Appに制御を戻す。

HTMLの送信時、カード会員の応答はパラメータ文字列として返される。指定URL（`HTTPS://EMV3DS/challenge`）にチャレンジの応答を付加し、そのURLへのlocation変更を発生させることで、フォームデータをWebビューのインスタンスに渡す。

**Seq 4.62 [Req 413]** URLの変更を監視し、URL（`HTTPS://EMV3DS/challenge`）のクエリパラメータからカード会員の応答を取得し、入力データを含むパラメータ文字列（HTML Action = GET）を返す。

**Seq 4.63 [Req 393]** 受信した入力データを変更せず、CReqのChallenge HTML Data Entryデータ要素としてACSに渡す。3DS SDKは、この入力データを変更または再整形してはならない。

**Seq 4.64 [Req 474]** カード会員が応答を送信したとき、3DS SDKが空の応答を受信した場合、HTMLが有効でないとみなす。この場合、Error Component = C、Error Code = 203のErrorメッセージ（A.9節で定義）をACSに返さなければならない。

3DS SDKはCReqをACSに送信する。

カード会員の応答例：`HTTPS://EMV3DS/challenge?response=12348&submit=verify`。3DS SDKが返す入力データ：`"challengeHTMLDataEntry": "response=1234&submit=verify"`。
