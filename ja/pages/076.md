**Seq 3.153 [Req 112]** ACSからAResまたはErrorメッセージを受信し、5.9.3節で定義するとおりに検証する。

メッセージにエラーがある場合、DSは処理を終了する。

**Seq 3.154 [Req 113]** DSの規則に従って必要な取引情報をログに記録する。

**Seq 3.155 [Req 411]** ACSに代わってDSがAResを生成する場合（例えば、DSがTransaction Status = Aを返す場合）、ACS Reference NumberにDS Reference Numberを、ACS Transaction IDにDS Transaction IDを設定する。また、AResで必要となるその他のACSデータ要素をすべて、DSの機能に応じて設定する。

**Seq 3.156 [Req 114]** [Req 100]で確立したセキュアな接続を使って、ACSから受信したAResを3DS Serverに送信する。

#### 手順10：3DS Server

3DS Serverは、次を実施しなければならない。

**Seq 3.157 [Req 115]** DSからAResまたはErrorメッセージを受信し、5.9.4節で定義するとおりに検証する。

メッセージにエラーがある場合、3DS Serverは処理を終了する。

**Seq 3.158 [Req 116]** 認証済み取引（Transaction Status = YまたはA）について、次を実施する。

a. 支払認証（01-PA）の場合、ACSが生成したTransaction Status、ECI値、およびAuthentication Valueが、オーソリゼーション処理に提供されるようにする。

b. AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信する。

c. 手順22に進む。

**Seq 3.159 [Req 117]** チャレンジを伴う取引（Transaction Status = C）について、次を実施する。

a. 3DS Requestor Challenge Indicator、ACS Challenge Mandated Indicator、およびACS Rendering Typeなどに基づき、要求されたチャレンジを実施するかを評価する。

- 3DS Requestorがチャレンジを受け入れる場合：AResから必要な情報（表B.2で定義）を3DS Requestor Environmentに送信する。本要件のb〜eに進み、その後に手順11へ進む。
- 3DS Requestorが要求されたチャレンジを実施せずに続行する場合：DSからRReqを受信し、5.9.9節で定義するとおりに検証する。メッセージにエラーがある場合、3DS Serverは処理を終了する。表B.9で定義するとおりにRResを整形し、DSに送信する。それ以降の処理は3-D Secure処理の対象外である。3DS Serverは手順22に進んでもよい。

b. ブラウザ方式の実装について表B.3で指定する形式に従い、CReqを整形する。

c. CReqをBase64urlでエンコードする。

d. CReqを含むフォームを構築する。3DS Requestorが提供した場合は、3DS Requestor Session Data（表A.3で定義）も含める。
