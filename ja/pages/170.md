### 5.11 OReq／OResのメッセージ処理要件

Operationメッセージにより、DSは3DS ServerまたはACSに運用情報を伝えられる。支払／非支払認証取引から独立していても、関連していてもよい。EMV 3DSプログラム全体のシステムの健全性や管理に関する情報を伝えるために使用できる。例えば次の用途がある。

- 処理所要時間と性能の報告。
- エコシステム内の不正な参加者の検出と警告。
- 鍵交換・証明書更新・リマインダーのDSからの通知。
- 侵害された端末についての情報交換。

Operationメッセージを使用するDSは、次を実施しなければならない。

**Seq 5.116 [Req 435]** 表B.10で定義するとおりに確立した受信側（3DS ServerまたはACS）とのセキュアな接続を使い、OReqまたは一連のOReqを準備してシーケンス番号順に送信する。

**Seq 5.117 [Req 436]** 受信側への最初のTCP/IP接続とTLSハンドシェイクを完了できない場合、直ちに接続を再試行する。

**Seq 5.118 [Req 437]** 2回目も完了できない場合、取引を終了し、正常に完了するまで24時間の期間内で60秒間隔の定期的な再試行を行う。

OReqの受信側（3DS ServerまたはACS）は、次を実施しなければならない。

**Seq 5.119 [Req 438]** 一連のすべてのOReqを受信し、表B.10に従って検証する。

- 存在するデータ要素が検証に失敗した場合、受信側が3DS ServerならError Component = S、ACSならError Component = Aを設定し、Error Code = 203のErrorメッセージ（A.9節で定義）をDSに返す。
- 必須データ要素が欠ける場合、受信側が3DS ServerならError Component = S、ACSならError Component = Aを設定し、Error Code = 201のErrorメッセージ（A.9節で定義）をDSに返す。

**Seq 5.120 [Req 439]** 表B.11で定義するセキュアな接続を使い、OResを準備してDSに送信する。

Operationメッセージを使用するDSは、次を実施しなければならない。

**Seq 5.121 [Req 440]** OResを受信し、表B.11に従って検証する。検証失敗時の処理は次ページに続く。
