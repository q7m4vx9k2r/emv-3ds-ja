# PDF 73ページ — 日本語参考訳

> 非公式の日本語参考訳。原本のページ単位で対応しています。全文翻訳は未完了です。図内の文字は英語原文のままです。

**Seq 3.134 [Req 98]** Cardholder Account Numberが、3-D Secureメッセージを処理できるACSを持つアカウント範囲に含まれるかを判定する。

含まれない場合、DSは3DS Serverに、個々のDSが定義する適切な値をTransaction Statusに設定したARes（表B.2で定義）を返し、処理を終了する。

**Seq 3.135 [Req 99]** 後にRReqを処理する可能性に備え、3DS Server URLをDS Transaction IDとともに保存する。

**Seq 3.136 [Req 100]** 6.1.3.1節で定義するとおりにACSとのセキュアな接続を確立する。

ACSとの接続を確立できない場合、DSは[Req 233]に従って処理し、処理を終了する。

注：DSは複数のACS URLを管理してもよい。最初に試したURLが利用できない場合、代替URLのいずれかへの接続を試みる。

DSは、次を実施しなければならない。

**Seq 3.137 [Req 101]** [Req 100]で確立したセキュアな接続を使って、AReqをACSに送信する。

ACSからAResを受信しない場合（5.5節で定義）、DSは[Req 235]で指定するメッセージを3DS Serverに返し、処理を終了する。

#### 手順8：ACS

ACSは、次を実施しなければならない。

**Seq 3.138 [Req 102]** DSからAReqを受信し、5.9.2節で定義するとおりに検証する。

メッセージにエラーがある場合、ACSは処理を終了する。

**Seq 3.139 [Req 103]** 認証を要求している消費者端末に対応しているかを確認する。

対応していない場合、ACSはDSに、Transaction Status = U、Transaction Status Reasonコード = 03のAResを返し、処理を終了する。

注：ACSは、AReqで受信したブラウザ情報（A.6節で定義）と3DS Methodを使い、端末の識別、取引リスクの評価、認証を完了できるかの判定を行う。Decoupled Authenticationを使用する場合、ACSがカード会員を認証する代替手段を持つなら、取引を開始した消費者端末に対応する必要はない。

**Seq 3.140 [Req 410]** 3DS Method IDがある場合、以前の3DS Method実行のデータを取得する。

**Seq 3.141 [Req 319]** ACSは、フリクションレス取引の一部としてカード会員との対話を開始してはならない。カード会員との対話は、チャレンジフローの一部として実施しなければならない。

**Seq 3.142 [Req 104]** ACS Transaction IDを生成する。
