| Term | Definition |

| Challenge Flow | A 3-D Secure flow that involves Cardholder interaction as defined in<br>Section 2.5.2. |
| Challenge Request<br>(CReq) Message | An EMV 3-D Secure message sent by the 3DS SDK or 3DS Server where<br>additional information is sent from the Cardholder to the ACS to support<br>the authentication process. |
| Challenge Response<br>(CRes) | The ACS response to the CReq message. It can indicate the result of the<br>Cardholder authentication or, in the case of an App-based model, also<br>signal that further Cardholder interaction is required to complete the<br>authentication. |
| Consumer Device | Device used by a Cardholder such as a smartphone, laptop, or tablet that<br>the Cardholder uses to conduct payment activities including authentication<br>and purchase. |
| Decoupled<br>Authentication | Decoupled Authentication is an authentication method whereby<br>authentication can occur independent from the Cardholder’s experience<br>with the 3DS Requestor. The authentication method used for Decoupled<br>Authentication is outside the scope of this specification. However, one<br>method could be a push notification to a banking app that completes<br>authentication and then sends the results to the ACS.<br>Decoupled Authentication is applicable to all Device Channels. |
| Decoupled<br>Authentication Fallback | An additional challenge option for an ACS during the Challenge process.<br>By returning Transaction Status = D in the RReq message, the ACS<br>requests that the 3DS Server initiate a subsequent 3DS authentication<br>using Decoupled Authentication. |
| Device Binding | In this specification, the process to link the Consumer Device used for a<br>transaction to the Cardholder Account and/or Cardholder. |
| Device Channel | Indicates the channel from which the transaction originated. Either:<br>• App-based (01-APP)<br>• Browser-based (02-BRW)<br>• 3DS Requestor Initiated (03-3RI) |
| Device Information | Data provided by the Consumer Device that is used in the authentication<br>process. |
| Digital signature | An asymmetric cryptographic method whereby the recipient of the data<br>can prove the origin and integrity of data, thereby protecting the sender of<br>the data and the recipient against modification or forgery by third parties<br>and the sender against forgery by the recipient. |
| Digital wallet | A software component that allows a user to make an electronic payment<br>with a financial instrument (such as a credit card) while hiding the low-level<br>details of executing the payment protocol, including such tasks as entering<br>an account number and providing shipping information and Cardholder<br>identifying information. |
